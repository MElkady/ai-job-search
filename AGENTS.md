# Agent Guidelines: AI Job Search

This workspace is structured to manage job search activities, scraper tools, CVs, cover letters, and interview preparation.

## Thin-Pointer Design (Single Source of Truth)

To prevent duplication and configuration drift across different AI agent frameworks (Claude Code, Kiro CLI, Google Antigravity, Codex, Cursor, Gemini CLI, etc.), this workspace uses a unified thin-pointer design. All agent runtimes should load the canonical specifications and candidate profiles from the files and directories below:

1. **Personal Candidate Profile:**
   - The candidate profile, contact details, education, and target preferences are defined in [CLAUDE.md](CLAUDE.md) and the individual profile methodology files under [.claude/skills/job-application-assistant/](.claude/skills/job-application-assistant/) (specifically `01-*.md` etc.).
2. **Canonical Workflow Specifications:**
   - The step-by-step instructions and triggers for tasks (setup, scrape, rank, apply, upskill, interview) are defined in the [.claude/](.claude/) directory (specifically under `.claude/skills/` and `.claude/commands/`).
   - Do not duplicate these rules or specifications. Treat `.claude/` files as the single source of truth.
3. **Portal Search Skills:**
   - Job-portal search CLIs live under [.agents/skills/](.agents/skills/) in the portable Agent Skills format (with a `SKILL.md` per portal). Codex and Antigravity discover these automatically; the `/scrape` workflow in [.claude/skills/job-scraper/](.claude/skills/job-scraper/) orchestrates them.

## Kiro (CLI and IDE)

Kiro CLI and the Kiro IDE run the same workflows from the same files as Claude Code. [.kiro/](.kiro/) holds no workflow content, only generated pointers:

- `.kiro/skills/<name>/SKILL.md` - one per `.claude/commands/*.md` and `.claude/skills/*/SKILL.md`. Each contains frontmatter (so Kiro lists it as `/<name>` and can auto-trigger it) plus an instruction to follow the `.claude/` source. The job scraper is `/scrape`, as in Claude Code.
- `.kiro/agents/ai-job-search.json` - the same pre-approved commands as `.claude/settings.json`, and `CLAUDE.md` loaded as context.
- `.kiro/steering/candidate-profile.md` - always-on steering that includes `CLAUDE.md` by file reference, so the IDE's default agent gets the profile too.

All three are generated by `python3 tools/sync_kiro.py` and checked in CI with `--check`. Never edit them by hand; edit `.claude/` or `CLAUDE.md` and re-run the script. Because every runtime reads and writes the same profile files, search queries and `job_scraper/` state, you can switch between Claude Code, Kiro CLI and the Kiro IDE mid-search.

**Kiro CLI:** start a session with the agent so its allowlist applies:

```bash
kiro-cli chat --agent ai-job-search
# or once: kiro-cli settings chat.defaultAgent ai-job-search
```

**Kiro IDE:** open the repository folder. The default agent picks up the skills (type `/scrape`, `/apply`, ...), this file and the profile steering with no setup. Shell commands the workflows run prompt for approval; choose "Always allow" to pre-approve one for this workspace. The `ai-job-search` agent is also available from the agent picker.

### Kiro tool mapping

The `.claude/` files name Claude Code tools. When running under Kiro, use the column for your runtime:

| Claude Code | Kiro CLI | Kiro IDE |
|---|---|---|
| `Read` (files, and PDFs/images for visual inspection) | `read` (Line mode for text, Image mode for rendered pages) | `read_file` (text, and images for rendered pages); `read_code` for source files |
| `Write`, `Edit` (`old_string` → `new_string`) | `write` (`create`; `strReplace` with `oldStr` → `newStr`) | `fs_write` (whole file); `str_replace` (`oldStr` → `newStr`) |
| `Glob`, `Grep` | `glob`, `grep` | `file_search`, `grep_search` |
| `Bash` | `shell` | `execute_bash` |
| `WebFetch`, `WebSearch` | `web_fetch`, `web_search` | `web_fetch`, `web_search` / `remote_web_search` |
| `Agent` tool / `general-purpose` agent | `subagent` tool, role `kiro_default`; pass the prompt as `prompt_template`, one stage per parallel agent | `invoke_sub_agent` with the `general-task-execution` agent; one call per parallel stage |
| `AskUserQuestion` | Ask in plain text and stop for the user's reply | Ask in plain text and stop for the user's reply |
| `TodoWrite` | `todo_list` | `todo_list` |
| `Skill(<name>)` | The `/<name>` skill in `.kiro/skills/` | The `/<name>` skill in `.kiro/skills/` (activate with `disclose_context`) |
| MCP tools (`mcp__<server>__<tool>`) | `@<server>/<tool>`; add servers with `kiro-cli mcp add` or in the agent config, and log in with `/mcp` | The server's tools once configured in `.kiro/settings/mcp.json` or `~/.kiro/settings/mcp.json` |
| `claude mcp add ...` | `kiro-cli mcp add ...` | Add the server to `.kiro/settings/mcp.json` (or the MCP panel) |
| `$SCRATCHPAD` (session scratchpad) | A temporary directory outside the repo, e.g. `SCRATCHPAD=$(mktemp -d)` | Same as Kiro CLI |
| `$ARGUMENTS` (command arguments) | Expanded into the pointer's `<arguments>` block | Not expanded; use the text typed with the slash command |

Rules that name Claude Code specifically are about the candidate, not the runtime, and apply unchanged. For example, the `/apply` cover-letter rule on naming AI tooling reflects what the candidate has actually used; do not substitute "Kiro" unless the profile says so.

`tools/robots_check.py` honors `Disallow` rules for `*` and for `Claude-User`. Under Kiro it still honors every `*` rule; a rule that names only Kiro's own crawler token is not checked.
